# Agent Log — 2026-07-23 — algolia — cut SearchPage query volume from 4 requests to 1 per search

---
timestamp: 2026-07-23T08:00:00Z
action: removed unnecessary disjunctive-facet-count side-queries from the full /search page
context: user inspected the browser network tab after the previous session's "See all N
  results" fix and noticed the /search page's request payload contained 4 entries per
  search (requests[0..3]), not 1, and asked what requests[1] ("facetFilters: [[framework:
  vue],[type:content]], facets: docusaurus_tag") was for
outcome: |
  Explained: algoliasearch-helper automatically issues one extra facet-count side-query
  per attribute listed in `disjunctiveFacets` (drops that one facet's own filter, keeps
  the others, asks only for that facet's value counts, hitsPerPage:0) — needed only if
  the UI displays per-value result counts somewhere. `SearchPage/index.js`'s
  FrameworkSelectDropdown is a static hardcoded list that never reads these counts, so
  all 3 side-queries (for `type`, `framework`, `docusaurus_tag` — the last one added by
  the prior session's "See all results" fix) were pure overhead, quadrupling search
  volume on that page for nothing.
  Fixed by removing `disjunctiveFacets` from the algoliaHelper config entirely and
  building `facetFilters` directly (nested-array OR syntax, same convention
  `src/components/Search/util.ts`'s getCustomFacets() already uses for the popup) via
  `algoliaHelper.setQueryParameter('facetFilters', ...)`, bypassing the
  addDisjunctiveFacetRefinement API path that requires the side-queries. Necessary
  companion change: had to also replace the `addDisjunctiveFacetRefinement(...)` calls in
  `makeSearch()`, since calling that API on a facet no longer declared disjunctive throws
  at runtime — this was caught before verification, not shipped broken.
  Verified live via a fresh dev server + Playwright network intercept, both the
  single-tag case (5.35.0 + framework) and the homepage's two-tag OR case: exactly 1
  request now, with the same facetFilters shape/scoping as before the change.
learnings: |
  Correcting the record from yesterday's (2026-07-22) log: the "See all N results"
  scoping fix (searchLink.ts's `tag` param + SearchPage.js applying docusaurus_tag) was
  implemented and verified on 2026-07-22 but its commit was never actually made that day
  — it sat uncommitted alongside today's query-volume fix until the user asked for a
  commit message covering both together. Recorded here so the commit history and these
  logs stay consistent with what actually happened, since the 2026-07-22 log entry
  describes work that wasn't committed until 2026-07-23.
