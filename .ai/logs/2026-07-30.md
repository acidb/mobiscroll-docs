# Agent Log — 2026-07-30 — algolia — implement presentInV5 boolean-facet design to fix free-tier record overage

---
timestamp: 2026-07-30T00:00:00Z
action: implemented the agreed presentInV5 design to reduce Algolia record count back under
  the free-tier limit after v5.35.0 coverage was added
context: user reported that adding `/docs/5.35.0/**` crawling to search-config.json (recent
  commits from `5b11cfaf` onward) roughly doubled indexed records (v5.35.0 and v6 docs are
  ~90% identical) and pushed the Algolia account over its free-tier record limit. Explored
  several designs interactively with the user (full blacklist/whitelist diff artifact,
  maintenance-free no-filtering OR, anchor-based facetFilters whitelist) before settling on:
  v6 stays fully indexed; v5.35.0 keeps only its genuinely unique auto-generated content
  (duplicates pruned post-crawl); a single `presentInV5` boolean facet is stamped onto v6
  records post-crawl from a frozen (v5.35.0 never changes) anchor set, avoiding both a large
  per-query facetFilters whitelist and a blacklist that would need updating every time v6's
  auto-generated docs change.
outcome: |
  New `algolia/` folder (all Algolia-specific tooling, kept separate from the general-purpose
  `scripts/` directory, per user request):
  - `generate-v5-anchor-sets.js` — one-time script (not part of any workflow), diffs anchor
    ids (`#opt-`, `#event-`, `#method-`, `#type-`, `#renderer-`) between `docs/{fw}/_auto-generated`
    (v6) and `versioned_docs/version-5.35.0/{fw}/_auto-generated`. Run once; produced
    `v5-anchors.json` (321 anchors, the full frozen v5.35.0 set) and `v5-only-anchors.json`
    (6 anchors genuinely unique to v5.35.0 — the pre-rename `renderSchedule*`/`renderLabel*`
    renderers, superseded by `renderScheduler*` etc. in v6, consistent with the
    `renderSchedulerEvent` naming already noted in the 2026-07-24 log entries).
  - `lib.js` — shared plain-`fetch` helper against Algolia's REST API (browse + batch), no new
    npm dependency.
  - `prune-v5-duplicates.js` — deletes `docusaurus_tag:docs-default-5.35.0` records whose
    `anchor` isn't in `v5-only-anchors.json` (keeps unique-to-v5 entries and all non-anchored
    guide/landing pages untouched).
  - `tag-present-in-v5.js` — partial-updates every `docusaurus_tag:docs-default-<currentVersion>`
    record's `presentInV5` boolean from membership in `v5-anchors.json`. Derives "current
    version" from `versions.json`'s first entry, matching the existing convention in
    `src/components/Search/util.ts`'s `useCurrentVersion()`.
  Both wired as new steps in `.github/workflows/algolia-crawl-dev.yml`, right after the
  existing docsearch-scraper step, reusing the already-configured `ALGOLIA_APP_ID`/
  `ALGOLIA_ADMIN_API_KEY` secrets. `algolia-crawl.yml` (prod) intentionally left unchanged
  pending dev-index verification, per the plan.
  `search-config.json`/`search-config-dev.json`: added `anchor` and `presentInV5` to
  `custom_settings.attributesForFaceting`.
  Client-side (`src/components/Search/util.ts`, `src/theme/SearchBar/index.js`): replaced
  `getCustomFacets` with `getSearchScope(locInfo, currentVersion)`, which returns a `filters`
  string (not `facetFilters` — expressing "v5.35.0's own records OR (v6 records AND
  presentInV5:true)" is an OR of an AND, which facetFilters' array format can't represent) when
  on a v5.35.0 framework/component page. Added `transformItemsForLocation`/
  `rewriteUrlForLegacyV5` to rewrite v6-sourced hit URLs back to `/docs/5.35.0/...` on those
  pages, wired into `SearchBar/index.js`'s existing `transformItems` hook.
  `npm run typecheck` passes (2 pre-existing, unrelated errors in `HomepageFeatures/index.tsx`
  only).
  Known gap, explicitly not covered by the approved plan: `src/theme/SearchPage/index.js` (the
  full "See all N results" page) builds its own `facetFilters` independently via
  `getDefaultTags()`/`getDefaultFramework()` and was not updated — a v5.35.0-originated search
  that continues to the full search page will not get the presentInV5 OR-scope or URL rewriting
  until that page is updated too. Flagged to the user, not yet actioned.
learnings: |
  Algolia's `facetFilters` array format (used everywhere else in this project's search config)
  cannot express "OR of an AND" — only flat AND, or OR within a single array entry. Any future
  scoping logic that needs that shape has to use the `filters` string parameter instead (which
  supports parentheses), and the two can coexist in the same query (combined via implicit AND).
  Worth remembering if `getSearchScope`'s pattern needs extending again.

timestamp: 2026-07-30T03:00:00Z
action: fix — anchor-extraction regex in generate-v5-anchor-sets.js missed 4 of 9 real
  anchor prefixes, found while user asked to double-check the two generated JSON artifacts
context: user asked to confirm algolia/v5-anchors.json and algolia/v5-only-anchors.json were
  complete/correct, after the presentInV5 work had already been committed
  (8e13a744 "chore(search): reduce v5.35.0 index bloat with a presentInV5 boolean facet").
  Verified rather than assumed: grepped all `{#prefix-` patterns actually used across
  docs/*/_auto-generated and versioned_docs/version-5.35.0/*/_auto-generated.
outcome: |
  The regex only matched opt|event|method|type|renderer — five prefixes, based on
  writing-docs.md/CLAUDE.md's documented link-hash-prefix list. The real content also uses
  localization-, slot-, template-, and view- (9 total). This silently excluded entire
  auto-generated categories (localizations.md, view_*.md, Vue's slot-based renderers,
  template-*) from both v5-anchors.json and v5-only-anchors.json — meaning
  prune-v5-duplicates.js would have deleted every v5.35.0 record in those categories
  unconditionally (their anchors could never match the whitelist), and
  tag-present-in-v5.js would never have marked their v6 equivalents presentInV5:true —
  a real, silent content-loss bug once the crawl workflow actually runs, not yet triggered
  since the dev crawl hasn't been run since this was implemented.
  Fixed the regex to include all 9 confirmed prefixes, regenerated both artifacts:
  v6 anchors 332 -> 529, v5.35.0 anchors 321 -> 497, v5-only anchors 6 -> 36. Spot-checked the
  new v5-only-anchors.json: the additional 30 entries are consistently the same
  schedule->scheduler rename already identified in the 2026-07-24 log entries, now showing up
  across renderer-, slot-, and template- variants plus a full set of view-schedule-* option
  anchors — confirms the fix is catching a real, consistent pattern, not noise.
  Proposed and (pending) committed as a separate follow-up commit rather than amending the
  already-pushed 8e13a744, per this repo's "always create new commits" git safety rule.
learnings: |
  Don't trust a documented convention list (writing-docs.md/CLAUDE.md's 5-prefix anchor list)
  as exhaustive when writing extraction logic against real content — verify by grepping the
  actual files. The convention doc was itself incomplete (missing localization-/template-/
  view- entirely, and possibly written before those categories existed), and copying it
  into the regex propagated that gap into generated data silently.
