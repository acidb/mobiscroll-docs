  algolia-crawl.yml and algolia-crawl-dev.yml. This fixes the warning at its actual source —

  earlier, which only controls the Node version installed for the workflow's own script steps.
  Not yet run — will confirm no warning on the next real run of either workflow.
learnings: |
  Don't trust a single WebFetch summary of a GitHub releases page for version-currency

  GitHub REST API (api.github.com/repos/<owner>/<repo>/releases) directly gives an
  authoritative, structured answer instead.

timestamp: 2026-08-03T01:00:00Z
action: fix — algolia-crawl.yml (prod)'s "Build minified crawl config" step never exported
  ALGOLIA_INDEX_NAME to $GITHUB_ENV, so Plant freshness sentinel (and every later node step)
  crashed with "Missing required environment variable: ALGOLIA_INDEX_NAME"
context: user ran the prod workflow for the first time since the pipeline-mirroring commit and
  hit the crash. Root cause: when the sentinel/prune/tag steps were mirrored into
  algolia-crawl.yml earlier this session, the "Build minified crawl config" step itself wasn't
  checked closely enough — dev's version of that step captures INDEX_NAME and appends
  `ALGOLIA_INDEX_NAME=$INDEX_NAME` to $GITHUB_ENV (which then becomes an env var for every
  later step in the job automatically); prod's version only echoed the index name to the log
  and never exported it. algolia/lib.js's algoliaConfig() requires ALGOLIA_INDEX_NAME
  unconditionally, so every one of the four new node steps was doomed to fail the same way —
  the sentinel step just happened to run first.
outcome: |
  Added the same INDEX_NAME capture + `echo "ALGOLIA_INDEX_NAME=$INDEX_NAME" >>
  "$GITHUB_ENV"` line to algolia-crawl.yml's "Build minified crawl config" step, matching
  algolia-crawl-dev.yml exactly. "Guard against wrong index_name" (prod-only) is untouched —
  it re-derives ACTUAL_INDEX from the file itself rather than reading the new env var, which is
  redundant but harmless. Not yet re-run.
learnings: |
  When mirroring steps between two workflow files, checking that the *new* steps match isn't
  enough — an existing, unchanged-looking step (here, "Build minified crawl config") can be a
  silent prerequisite the new steps depend on. Should have diffed each shared step's full body
  between the two files, not just confirmed the new step list matched.
