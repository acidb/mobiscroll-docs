# Agent Log — 2026-08-11 — main — investigate large versioned_docs/version-6.1.0 diff after re-running docs:version

---
timestamp: 2026-08-11T00:00:00Z
action: investigated why `npm run docusaurus docs:version 6.1.0` produced ~886 modified files under versioned_docs/version-6.1.0
context: user request to explain the diff and trace it to the Docusaurus v3 migration
outcome: |
  Classified the 886 changed files: 594 are byte-identical to HEAD (git status false positive,
  stat-cache/CRLF noise — core.autocrlf=true with no eol=lf override for versioned_docs paths in
  .gitattributes, unlike docs/**/_auto-generated which has one). 141 are trailing-newline-only
  additions. 151 carry real content changes: HTML-entity unescaping (&#123;/&#125; -> {}), unescaped
  underscores in import paths, and an "[MbscLocale](#type-MbscLocale)" link reverting to plain text.
  Root cause: commit 07dde5d7 ("fix(llms): fix strip-jsx post-build script for Docusaurus v3 MDX
  compatibility") touched both docs/ and versioned_docs/ but applied opposite entity-escaping
  directions to the two trees, leaving docs/ (unescaped) and versioned_docs/version-6.1.0 (escaped)
  out of sync ever since. Re-running docs:version simply re-syncs the snapshot from current docs/,
  surfacing that drift as a large diff. Separately found unrelated, pre-existing dirty changes in
  docusaurus.config.js, version-map.json, and package-lock.json that blindly replace the literal
  string "6.1.0" with "5.35.0" (lastVersion, versions map, onlyIncludeVersions, and even an unrelated
  npm package's version field) — not caused by docs:version (native docs:version does not touch these
  files; versions.json itself has no diff). Flagged to user as a likely leftover from a manual/half-done
  version rollback, unrelated to today's docs:version run.
learnings: |
  .gitattributes only pins `docs/*/_auto-generated/**/*.md` to `eol=lf`; versioned_docs copies of the
  same generated files have no such rule, so on Windows with core.autocrlf=true git status can flag
  large swaths of versioned_docs as modified with zero real content difference (verify via
  `git hash-object` vs `git rev-parse HEAD:<path>` before trusting `git status` on this tree).
