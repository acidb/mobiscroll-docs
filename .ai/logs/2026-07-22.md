outcome: |
  Explained the config file is never fetched by anything automatically — it's read off
  local disk, piped through jq into a `.env` value, and handed to the docsearch-scraper
  Docker container at the moment a human runs the command; the container then makes real
  outbound HTTP requests to whatever's already live at those URLs. It has no relationship
  to this repo's build/deploy pipeline at all.
learnings: the two "automatic crawling" options differ in whether this repo's JSON file
  stays authoritative going forward — worth remembering before recommending either one:
  - Algolia-hosted Crawler: rules get manually re-entered into Algolia's own dashboard/API
    once; this repo's search-config.json then becomes disconnected/stale unless someone
    remembers to mirror future edits into Algolia's config by hand (a real drift risk).
  - CI-automated Docker (e.g. GitHub Actions cron): keeps this exact file as the live
    source of truth — a scheduled job just checks out the repo and re-runs the same
    jq+docker steps a human would, so whatever's committed here is what runs, automatically.

  "docs-default-6.1.0"]`) specifically for the homepage case, and getCustomFacets() wraps

learnings: |
  FUTURE CONSIDERATION (explicitly not implemented — user asked only to log this, not
  build it): `util.ts` still hardcodes version strings (`CURRENT_VERSION = "6.1.0"`, the
  `/\/5\.35\.0\//` regex) that will need manual updates on every future version bump.
  Proposed but deferred approach: derive these from Docusaurus's own version metadata via
  `useVersions('default')` (from `@docusaurus/plugin-content-docs/client`), which already
  reflects `lastVersion`/`onlyIncludeVersions` in `docusaurus.config.js` — the one place
  version bumps already have to happen (see Workflow H). That hook returns each version's
  name/path plus an `isLast` flag, so "current" vs "other" could be computed generically
  instead of hardcoded. Tradeoff: `getLocationInfo`/`getCustomFacets` are currently plain
  functions taking only `location`; this would require turning them into hooks (or having
  `SearchBar`/`SearchPage` call `useVersions()` and pass the result in), a real but modest
  refactor — worth revisiting if/when another version bump is planned.
